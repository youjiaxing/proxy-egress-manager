# 节点范围与质量记录（v0.2）

## 查看和配置

- 订阅来源点击“查看节点”，精确筛选该来源；节点页可搜索并切换卡片/表格。仅布局偏好保存在当前浏览器 localStorage，默认卡片。
- 分组点击“可用节点清单”，选择全部已启用订阅、指定订阅或指定节点。自动恢复只在允许范围里找，每轮最多三个候选；平时保持当前节点，不因延迟排名换节点，也不自动回切。
- 保存范围且当前节点仍在其中，不因保存动作断开连接；移除当前节点要明确确认，先撤销旧会话。固定或手动暂停不会被保存操作解除。
- 订阅代际、分组代际与节点配置指纹参与标识。订阅删除后即使槽位/名称复用，也不能继承旧授权。缺失的限定范围保持无候选，不扩大到全部。
- 无合格候选时依次在 1、5、15 分钟后重试，之后每 15 分钟；退避期间不重复探测失效当前节点。可手动重试一轮。原有持续 180 秒确认故障、身份有效期和调度失效即停继续生效。

## 质量详情

分组卡片和节点卡片/表格均可打开质量详情，提供最近 24 小时或 7 天的记录。运行分组复用已有探测采集，不添加未使用节点的周期监测。新安装/重启后的缺测区间不视为正常。

HTTP 显示 GET 响应头耗时，包括代理建连和目标响应；不同节点代际、目标、方法、探测配置和运行/候选/独立手动来源分别统计。失败耗时为空。成功次数和成功率不等于业务可用时间比例，更不是丢包率。相邻成功耗时绝对差的平均值不跨失败、超过 90 秒缺测、进程重启或配置恢复；它不代表网络线路抖动。重启前后同配置的均值可汇总，曲线和相邻差会断开。状态变化是采样观察，不提供精确故障起止或 SLA。

手动 HTTP/UDP 测试用独立 Mihomo 进程与专用网络，串行执行、有进度且可取消，不改变业务核心选择或租约。不包含现有业务会话或完整网关链路，也不能保证和业务会话得到相同出口。测试仍会占用服务器和订阅资源，只有明确点击才发出。

UDP 一次发送 20 个不同 STUN 事务，每次最多等 2 秒、间隔 200ms，不重传，整轮最多 60 秒。显示发出/收到样本数、往返未响应比例、成功样本 RTT 最小/平均/最大，以及目标和时间。未响应可能来自去程、回程或目标本身，不能称为整条业务线路的真实丢包率。没有记录时显示未知，不显示成 0%。

诊断容器限制 128 MiB、0.25 CPU，无宿主端口，只加入独立诊断网络；空闲不产生探测流量。业务核心与诊断核心仍共享宿主资源、远端订阅额度和外部网络，独立进程不意味着物理线路隔离。

## 历史与恢复

`quality.db` 独立于配置数据库，最多保留 7 天、5 万条或 32 MiB 记录内容，先到上限先清理；SQLite 索引/WAL/文件空间另有开销。详情显示实际最早记录和截断说明。常规样本最多显示最新 500 条，UDP 最近结果和状态变化从完整保留窗口分别取；状态变化最多展示 5000 条。提供独立 NDJSON 流式导出。

质量历史不进入配置备份。网页和离线恢复都保留本机历史并写恢复边界，新探测配置世代分开统计。来源/节点变化期间完成的手动结果只作历史，不变成新节点的验证资格。历史写入失败不授权业务，也不阻塞调度；界面提示记录可能缺失。

## v1 → v2 升级与降级

旧 format 1 配置迁移为 format 2，原分组默认使用全部已启用订阅。新格式严格保留范围限制。权威数据库改为 `state-v2.db`，旧 `state.db` 成为拒绝旧程序加载的墓碑；迁移成功后不能只换回旧镜像启动。

升级前停写并用旧镜像生成一致备份，另存旧 Compose、部署环境和镜像摘要。失败回退必须停止所有新组件（包括诊断核心），先私密保全失败数据库，再统一移除 v2 数据库及 WAL/SHM、ready/迁移标记与旧墓碑，用旧镜像从升级前 format 1 备份恢复，然后才启动旧版本。不要删除 `quality.db`，也不要复用残留 v2 文件执行下一次升级。回退丢失备份点后的配置变更。

普通用户不要手动清理这些文件。恢复任一步失败应保持停机，使用一致备份重新完成恢复；数据库丢失不能自动重建为无限制分组。上线后所有保留节点都需重新验证。

## 国家归属查询与限流

国家归属查询与连接可达是两个独立环节。TCP 成功但其国家服务限流时，不能把它说明为节点断线，也不能放行未经确认的 TCP 出口。UDP 国家查询仅用于展示，不参与准入。国家信息按查询模板和实际出口 IP 缓存 6 小时（进程内最多 512 项）；TCP 出口 IP 和授权有效期仍每轮重新验证，不因缓存延长。缓存过期后查询失败保持关闭；失败短暂缓存 60 秒，429 按服务退避 1 至 60 分钟（缺省 15 分钟），不为每个候选重复轰炸同一服务。切换国家服务不复用旧服务的缓存。

质量页默认先显示当前入口状态、当前节点的运行检查指标和延迟趋势；可切换检查目标。检查失败在曲线上以红标表示，缺测不连线。候选检查、历史节点和详细说明折叠展示；手动 UDP 未响应比例独立呈现，不与日常检查失败比例混用。

## 手动选择与操作反馈（v0.3.2）

手动“自动查找”连续检查允许范围内的候选（优先名称标注美国者，仍以实际国家验证为准），找到合格且不冲突的出口即停止；单次最多 100 个，界面显示总数与本次上限。每个候选结束后释放控制锁，其他分组继续原有验证。后台自动恢复仍每轮最多 3 个并保留退避，不增加未使用节点的日常巡检。指定节点只验证那一个。手动查找失败且原节点仍有有效授权时保留原节点；不能把“查找任务结束”当作“已应用新节点”。

分组卡片就地显示进度、当前候选、已检查数量、逐节点结果和最终是否应用；最后操作结果随配置持久保存。停止查找采用协作标记，当前检查自然结束，提交新授权前再次确认停止请求；不会强行取消配置事务。刷新页面仍可看到正在查找并请求停止。范围、来源身份、检测设置或恢复世代变化时中止旧查找，不继续使用旧快照。服务重启将未结束的操作标为中断。

修改允许范围时，若没有可用当前节点，会保存后立即按新范围查找，不等待旧退避；有可用节点且仍在范围内则保留会话。手动暂停或固定不会因保存清单解除。进度反馈明确区分清单保存、节点已应用、未通过验证、取消与中断。

### 自动优选与手动节点池

分组提供“自动优选”和“手动组池”。自动优选按需评估当前允许范围（最多 100 个），不改变业务节点或租约；依据完整 TCP 出口验证、与其他组 TCP 出口是否冲突，以及同次测试的 HTTP 失败数、较慢 HTTP 目标耗时排序；候选不额外探测 UDP。仅推荐本次 HTTP 检查均成功且有耗时记录的合格节点，最多 3 个，供确认后保存为节点池；数量不足时不凑数。不把一次测试叫作长期稳定。

手动组池逐行展示节点/订阅、上次验证与原因/时间、较慢 HTTP 目标耗时、已有同配置单目标的最近 24 小时检查计数和相邻耗时差，并可打开质量详情。没有数据时显示未评估或无历史统计，不填为 0。可多选、搜索、只看上次通过的节点；正常保持池内一个，故障后在池内换。指定节点池按确认列表顺序验证，UI 默认按评估结果/延迟排列。保存范围与授权是两步，启用前仍完整复验，旧评估不授予转发权限。

## 分组配置流程（v0.3.4）

卡片统一从“配置分组”进入：选择“自动优选节点池”，按需评估并确认推荐；或“手动选择多个节点”，对照质量和延迟多选。已有评估可直接查看并调整，无须重新测速。保存仍保留暂停/固定状态；分组可用且当前节点仍在新池内时保持连接；暂不可用时，修改范围会启动查找，移出时需确认断开并验证新节点。

卡片“更多操作”中的“立即切换当前节点”只更换当前使用的一个节点，不修改节点池；检查、固定、重试和删除也在这里。配置页、帮助与操作结果明确区分节点池保存和业务可用，不将评估完成当成已经应用。

## 连续配置与结果（v0.3.5）

配置流程显示选择方式、挑选节点、确认配置、查看结果四步。多选后先预览拟保存清单和对当前连接的影响，确认前不写配置；返回修改或明确失败会保留本次选择。打开已有指定订阅范围时保留原模式，不悄悄改成指定节点。

自动评估和保存留在当前流程内显示进度，关闭会提示后台继续。评估完成进入推荐多选；保存结束显示当前节点池、实际使用节点、可用状态和原因。暂停/固定/未通过验证时提供对应的启用、解除固定或重试操作，不静默改变状态。网络中断或结果无法核对时不自动重提配置，先查看实际状态；历史结果不代替当前授权。

## 简单节点面板（v0.3.7）

节点卡片突出名称和带颜色的 HTTP 延迟，点击数字直接测试一个节点，显示测试中、毫秒、超时或失败。可勾选多个后批量测试，卡片高亮选中；批量执行期间读取已完成记录逐步更新。协议核验、优先级和管理折叠到详情。最新有效手动失败不会回退显示旧成功；来源身份已变化的测试不作为新结果。只在明确点击时探测，未增加周期测速；请求耗时不是 ICMP ping，也不证明完整出口准入。

## TCP 准入与 UDP 参考指标

自 v0.3.8 起，分组可用、自动切换与手动选节点均以 TCP 为硬性条件，仍要求全部 TCP 身份目标成功、美国国家归属和组间 TCP 出口独立。UDP 连通、耗时、国家与出口 IP 均只展示；失败或地址变化不暂停 TCP、不触发换节点。历史旧版可用状态采用当时的双协议规则，不能当作新版 TCP 的连续可用率。未使用节点仍不新增周期探测。Google Fonts 等具体网站需单独验证，不因通用 TCP 检查成功就宣称业务目标可用。

## 省流检测频率

从 v0.3.9 起，设置页可分别配置 TCP 检查间隔与 UDP 观测间隔（新字段缺省 1800 秒，旧备份恢复自动补齐）。日常只检查每组当前节点；未使用节点没有周期测量。候选筛选使用 TCP 条件，新的业务节点复验时尝试一次 UDP，之后按每组/实际节点身份与目标计时；手动 UDP 诊断仍只在点击时执行。

本次用户选择的线上省流档是 TCP 300 秒、UDP 1800 秒、调度健康宽限 420 秒、身份有效期 900 秒；TCP 故障确认阈值仍 180 秒，请求超时仍 8 秒。后台每轮结束后等待检查间隔，因此真实间隔还包含本轮耗时。故障发现与切换通常慢至约 5–10 分钟，不能承诺精确恢复时限。授权与身份仍到期关闭，不采用无限续期。已有部署的 TCP 配置不由软件更新自动覆盖，须通过管理设置明确应用。

未安排 UDP 的 TCP 轮次不发送 STUN，也不生成成功/失败样本；分组保留上次 UDP 结果及实际观测时间。重启或节点/来源身份、UDP 目标、观测频率变更后重新建立计时；新节点不继承旧节点 UDP 状态。省流档两组健康日常用量约 8 MB/天、240 MB/30 天为旧频率实测的比例估算，不含业务、手动测试、恢复候选、订阅下载和协议封装/重传；须以运行后的实际账本确认，不能等同机场计费。
