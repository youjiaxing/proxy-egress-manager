# 节点范围与质量记录（v0.2）

## 查看和配置

- 订阅来源点击“查看节点”，精确筛选该来源；节点页可搜索并切换卡片/表格。仅布局偏好保存在当前浏览器 localStorage，默认卡片。
- 分组点击“可用节点清单”，选择全部已启用订阅、指定订阅或指定节点。自动恢复只在允许范围里找，每轮最多三个候选；平时保持当前节点，不因延迟排名换节点，也不自动回切。
- 保存范围且当前节点仍在其中，不因保存动作断开连接；移除当前节点要明确确认，先撤销旧会话。固定或手动暂停不会被保存操作解除。
- 订阅代际、分组代际与节点配置指纹参与标识。订阅删除后即使槽位/名称复用，也不能继承旧授权。缺失的限定范围保持无候选，不扩大到全部。
- 无合格候选时依次在 1、5、15 分钟后重试，之后每 15 分钟；退避期间不重复探测失效当前节点。可手动重试一轮。原有持续 180 秒确认故障、身份有效期和调度失效即停继续生效。

## 质量详情

分组卡片和节点卡片/表格均可打开质量详情，提供最近 24 小时或 7 天的记录。运行分组复用已有探测采集，不添加未使用节点的周期监测。新安装/重启后的缺测区间不视为正常。

HTTP 显示 GET 响应头耗时，包括代理建连和目标响应；不同节点代际、目标、方法、探测配置和运行/候选/独立手动来源分别统计。失败耗时为空。成功次数和成功率不等于业务可用时间比例，更不是丢包率。相邻成功耗时绝对差的平均值不跨失败、超过 90 秒缺测、进程重启或配置恢复；它不代表网络线路抖动。重启前后同配置的均值可汇总，曲线和相邻差会断开。状态变化是采样观察，不提供精确故障起止或 SLA。

手动 HTTP/UDP 测试用独立 Mihomo 进程与专用网络，串行执行、有进度且可取消，不改变业务核心选择或租约。不包含现有业务会话或完整网关链路，也不能保证和业务会话得到相同出口。测试仍会占用服务器和订阅资源，只有明确点击才发出。

UDP 一次发送 20 个不同 STUN 事务，每次最多等 2 秒、间隔 200ms，不重传，整轮最多 60 秒。显示发出/收到样本数、往返未响应比例、成功样本 RTT 最小/平均/最大，以及目标和时间。未响应可能来自去程、回程或目标本身，不能称为整条业务线路的真实丢包率。没有记录时显示未知，不显示成 0%。

诊断容器限制 128 MiB、0.25 CPU，无宿主端口，只加入独立诊断网络；空闲不产生探测流量。业务核心与诊断核心仍共享宿主资源、远端订阅额度和外部网络，独立进程不意味着物理线路隔离。

## 历史与恢复

`quality.db` 独立于配置数据库，最多保留 7 天、5 万条或 32 MiB 记录内容，先到上限先清理；SQLite 索引/WAL/文件空间另有开销。详情显示实际最早记录和截断说明。常规样本最多显示最新 500 条，UDP 最近结果和状态变化从完整保留窗口分别取；状态变化最多展示 5000 条。提供独立 NDJSON 流式导出。

质量历史不进入配置备份。网页和离线恢复都保留本机历史并写恢复边界，新探测配置世代分开统计。来源/节点变化期间完成的手动结果只作历史，不变成新节点的验证资格。历史写入失败不授权业务，也不阻塞调度；界面提示记录可能缺失。

## v1 → v2 升级与降级

旧 format 1 配置迁移为 format 2，原分组默认使用全部已启用订阅。新格式严格保留范围限制。权威数据库改为 `state-v2.db`，旧 `state.db` 成为拒绝旧程序加载的墓碑；迁移成功后不能只换回旧镜像启动。

升级前停写并用旧镜像生成一致备份，另存旧 Compose、部署环境和镜像摘要。失败回退必须停止所有新组件（包括诊断核心），先私密保全失败数据库，再统一移除 v2 数据库及 WAL/SHM、ready/迁移标记与旧墓碑，用旧镜像从升级前 format 1 备份恢复，然后才启动旧版本。不要删除 `quality.db`，也不要复用残留 v2 文件执行下一次升级。回退丢失备份点后的配置变更。

普通用户不要手动清理这些文件。恢复任一步失败应保持停机，使用一致备份重新完成恢复；数据库丢失不能自动重建为无限制分组。上线后所有保留节点都需重新验证。
